## 3. Detailed Empirical Findings & Review-Identified Gaps

### 3.1 `effect@4.0.0` Workflow, Cluster, Snowflake & Graph APIs

1. **`Workflow.make` & `Workflow.execute`:** `effect@4.0.0` requires `Workflow.make(name, { payload, idempotencyKey, success?, error? })` (single-arg throws `Cannot read properties of undefined (reading 'payload')`). `Workflow.execute` supports `{ discard? }` only — there is no `detached?` option (`Workflow.d.ts:43-45`).
2. **Synchronous `DurableDeferred.tokenFromExecutionId` & `Snowflake.Generator.nextUnsafe()`:** Both are synchronous (`Token` and `Snowflake` respectively; neither yields an `Effect`). `Snowflake.ts:94` has `nextUnsafe()`, no `next` property/method.
3. **`MessageStorage.MessageStorage` & Layer deps:** `MessageStorage` is a class+namespace whose Context tag is `MessageStorage.MessageStorage`; `MessageStorage.makeEncoded` requires only `Snowflake.Generator` (`MessageStorage.d.ts:473`), while `ShardingConfig` is consumed by `Sharding.layer`.
4. **`effect/Graph` topological sorting (`Suite 0`):** `effect/Graph` `4.0.0` has no `Graph.toposort` (`hasGraphToposort: false`); `Graph.topo(dag)` yields a `NodeWalker` requiring `Graph.values(Graph.topo(dag))`. `Graph.isAcyclic` + `Graph.stronglyConnectedComponents` cleanly detected `[step-a, step-b, step-c]`.
5. **Orphan `entityType` starvation (`Suite 4 -> 5` discovery):** Between Runs 4 and 5, leaving 20 un-cleared synthetic `OccBurst` envelopes (`processed = false`) with no registered entity manager caused `Sharding`'s `Storage read loop` to retry `"Could not find entity manager for address"` continuously, timing out `Suite 5`'s 4 s post-load resume window until `OccBurst` rows were cleaned (`clearAddress`). (`Sharding.ts` also retries missing managers up to `2 × entityRegistrationTimeout` before failing envelopes with `Effect.die`). WF-2 must include startup orphan-entity quarantine/migration.

### 3.2 Omnigraph `0.14.0` GQ 2.1, Concurrency, Policy & Storage Behavior

1. **GQ 2.1 syntax & nullable clears (`Suite 1` + `Supp Probe 1`):**
   - `= null` fails `omnigraph lint` (`is null` is required); bare `null` literals in `insert`/`update` fail lint.
   - Invoking `wf_reset_message_for_clear` with typed nullable params `{ clearReplyId: null, clearReadMs: null }` cleared both fields on Lance (`nullClearedReplyId: true`, `nullClearedLastReadMs: true`).
   - Uncorrelated `not { $r: WfReply ... }` anti-joins lint cleanly and match expected semantics.
   - **`clearReplies` P0 flaws found in spike driver by reviews:** Spike `omnigraph-message-storage.ts:659-670` released `writeMutex` between Commit 1 and Commit 2, omitted `$expectedReplyId` CAS in Commit 2 (`wf_reset_message_for_clear`), unconditionally deleted `kind = "interrupt"` even when `expectedReplyId` was set, and only repaired dangling requests inside boot `resetShards` (an intra-process Commit-2 failure would leave `processed = true` wedged until restart!). Production WF-2 fixes all four.
2. **Snowflake `> 2^53` precision loss:** Nov 2026 Snowflakes (`248476693641609216`) exceed `Number.MAX_SAFE_INTEGER` (`2^53 - 1`), losing low bits in Omnigraph `I64` JSON serialization; schemas sort on 20-char zero-padded `seqKey: String @index`.
3. **`unprocessedMessages` P0 flaws found by reviews:** Filtering `opts.addresses` in JS _after_ `limit 1024` in `wf_unprocessed_candidate_messages` (`workflows.gq:106`) starves resident entities if >=1,024 older rows exist; reading outside `writeMutex`, sleeping inside `writeMutex` during 412 backoff (`omnigraph-message-storage.ts:431`), and omitting `and processed = false` in `wf_claim_messages` risk clobbering concurrent resets. Also `JSON.parse` must guard corrupt rows individually (`MessageStorage.ts:825-898` defect handling).
4. **Hard actor concurrency cap of `16` (`HTTP 429`):** Pre-semaphore iterative Run 3 hit `TooManyRequestsError: actor in-flight count cap 16 exceeded` under 40-fiber concurrency. Bounding in-process concurrency (`maxConcurrentHttp = 12`, shared process-wide across `harness-cli` callers) plus `429` retry eliminated drops (`Suite 4` `20`-fiber burst with `maxConcurrentHttp: 32` hit `4` `429` retries and finished `20/20`).
5. **`writeMutex: true` vs `false` (`Suite 4`, single `wf0-results.json` run):**

| Metric (`10 workflows × 8 activities = 80 activities`) | `useWriteMutex: true`             | `useWriteMutex: false`              | Ratio (`off / on`)       |

| Elapsed wall time                                      | **5,001.63 ms**                   | **12,248.93 ms**                    | **2.45× slower**         |

| Write commits                                          | **201**                           | **1,375**                           | **6.84× more**           |
| OCC (`412`/`409`) retries                              | **10**                            | **1,158**                           | **115.8× more**          |
| `unprocessedMessages` P50 / P95 / Max                  | **85.43 / 885.33 / 1,041.25 ms**  | **101.37 / 348.92 / 2,019.95 ms**   | queued burst vs retry    |
| `saveEnvelope` P50 / P95 / Max                         | **529.46 / 919.13 / 1,001.24 ms** | **135.91 / 829.65 / 1,112.15 ms**   | queued vs contending     |
| `saveReply` P50 / P95 / Max                            | **334.24 / 790.86 / 995.92 ms**   | **101.81 / 5,779.90 / 6,959.88 ms** | **7.31× worse P95 tail** |

_(Uncontended single-workflow latencies in `Suite 2`, 42 reads / 23 writes / 3 OCC retries: `unprocessedMessages` `1.75–38.13 ms`, `saveEnvelope` `6.06–14.69 ms` on 9/10 calls with 1 OCC retry at `89.31 ms`, `saveReply` `12.47–13.72 ms`, `requestIdForPrimaryKey` `2.40–8.36 ms`, `repliesForUnfiltered` `2.83–3.52 ms`, `clearReplies` `19.08 ms`, `resetShards` `9.23 ms`.)_ 6. **Lance amplification, `optimize`, `cleanup`, and admission lock retention (`Suite 5` + `Probe 2`):**

- `Suite 5`: `harness-workflows.omni` grew to **172,436,084 B** for 475 entities (**225,271 B** NDJSON = **`~765×`** amplification). Offline `omnigraph optimize` compacted fragments `235 -> 1` (`173,002,572 B`), while **`Probe 2` proved `omnigraph cleanup --keep 1 --confirm` reclaimed `5,553,119 B` (`8,685,497 -> 3,132,378 B`, removing 81 versions across 3 datasets)** while preserving live rows (`rowsAfterCleanup: 1`).
- **Omnigraph `0.14.0` CLI quirks:** Both `optimize` and `cleanup` reject `--as` (despite `--help` listing it) and `optimize` rejects inline `http://` URLs (`"inline access supports local storage only"`). Worse, inline `file://` runs of `optimize` and `cleanup` **retain `__cluster/lock.json` on exit** (`"command completion alone does not release this lock"`), requiring `omnigraph cluster force-unlock` after confirming quiescence.

7. **Disjoint Cedar policies verified (`Suite 1` + `Probe 3`):**
   - `Suite 1`: On shared `graph.policy.yaml`, `agent-mcp` read `wf_count_all` (`true`) and was blocked on mutation (`403`).
   - `Probe 3`: Splitting `cluster.yaml` into **disjoint** `applies_to: [harness]` (`graph.policy.yaml`) and `applies_to: [harness-workflows]` (`workflows.policy.yaml`, `admins: [harness-cli]` only, separating `[read, export, change]` / `[invoke_query]` / `[branch_*]`) passed `omnigraph cluster validate` (`31 resources, 54 edges`) and blocked `agent-mcp` on **both reads (`404`) and mutations** to `harness-workflows` while preserving `agent-mcp` reads on `harness`!

### 3.4 Daemon Socket, `done` Protocol, Drift & Spec Lint Findings (`Suite 6` + Reviews)

- **Socket path (`Suite 6`):** `.harness/daemon.sock` under worktree root is **97 B** vs **`70 B`** under `<git-common-dir>/harness/daemon.sock` (`107 B` Linux `UNIX_PATH_MAX` limit). Existing `apps/harness-mcp/src/daemon/unix-socket-daemon.ts` rejects external linked worktrees via `isPathInsideRoot`, lacks startup version/capability handshake on `"already-alive"`, and `libs/harness/infra/src/unix-socket-daemon-live.ts` couples RPCs to a `5000 ms` `DAEMON_SOCKET_TIMEOUT_MS`.
- **Lifecycle / `done` protocol bugs found by reviews:**
  - `apps/harness-cli/src/commands/verify-and-done.command.ts` (`handleDone`) rejects empty stdin in non-TTY pipes (`"empty Stop hook stdin payload"`) and returns **`exitCode: 0`** with `{ decision: "block" }`; `ShipWorkflow` needs an explicit non-hook `--cli` mode (or JSON decision check).
  - `apps/harness-cli/src/commands/omnigraph-lifecycle.ts:363-378` runs `killOmnigraphServerPidIfAlive` **before** `rmRecursiveSync`; WF-2 must export `harness-workflows` **before** server kill (with offline `omnigraph export --target file://...` fallback), and `apps/harness-cli/src/commands/omnigraph-auth-and-drift.ts` `CONFIG_DIGEST_FILES` must include `workflows.schema.pg`, `workflow-queries/workflows.gq`, and `workflows.policy.yaml`.
  - `apps/harness-cli/src/commands/done-omnigraph-helpers.ts:490-561` executes `mode: "overwrite"` + `mergeOmnigraphBranch` in one call, requiring an injected pre-merge projection hook for WF-6 (while keeping `harness-workflows` untouched by `done`).
