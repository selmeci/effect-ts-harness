## 1. RuleSynthesizer facts — PARTIAL

- Real line ranges (libs/harness/gates/src/rule-synthesizer.ts, 729 lines): `decideRuleSynthesizer` L538-714 (RFC says L580-728; L716-729 is the `RuleSynthesizer` export object); `computeLggRule` L190-~293 (RFC L190-260); `variabilizeGraphTokenWithMap` L144-~178 (RFC L137-169; L137-142 is SCOPE_PATH_REGEX/extractScopePrefix); `CASCADE_STAGE_NAMES` L31-36 correct; `IMMUTABLE_TCB_PATHS` L49-58 correct.
- CASCADE_STAGE_NAMES = Stage1_PushoutWellFormedness, Stage2_PositiveReplay, Stage3_ZeroFalsePositive, Stage4_ImmutableTcbAndQuality (DPO semantics). RFC-0014 "mirrors" them with different names/semantics; the shared notion is only "4 sequential stages". Stage 4 in the real code does quality-threshold only; the TCB check is a pre-flight at L541-551 (stage label Stage4 but run first).
- IMMUTABLE_TCB_PATHS exact (8): gates/src/policy.ts, verify-stamp.ts, ast-cache.ts, plugins/ast-gate-visitors.ts, mutation-check.ts, mutation/mutant-ast-generator.ts, rule-synthesizer.ts, apps/harness-cli/src/index.ts. RFC §3.3.2 lists 5 of them, omits ast-gate-visitors.ts and mutant-ast-generator.ts.
- "Plotkin LGG / First-Order Graph Anti-Unification / AlphaEvolve": this is the repo's own self-description (RFC-0005 L40, ADR-0010 L66, rule-synthesizer.ts L685). In code, computeLggRule is set-difference over opaque string tokens (removedEdges/addedEdges/preserved nodes) plus a regex that replaces `libs|apps/<scope>/` with `?Scope` vars. No term/tree anti-unification. "AlphaEvolve cascade" is a label for a plain 4-check pipeline (no evolutionary search). RFC-0014 §4.2 claims it is "extending Plotkin's LGG already used in computeLggRule" — over-claim: the TS-AST anti-unifier is new work, not an extension of existing code. Also decide takes `RuleSynthesizerInput` (graph tokens + `healthyCorpusSnapshots`), nothing reusable for AST ledger records.
- RFC §2.1 L53 link `rule-synthesizer.ts#L31-L135` is fine as a range of schemas.
- Existing default `minQualityMillis` = 500 (L~625), RFC-0014 uses 750. Not a contradiction but not "mirroring".

## 2. TCB status of registries — PARTIAL / design gap

- `libs/harness/gates/src/plugins/gate-plugin-registry.ts` is NOT in IMMUTABLE_TCB_PATHS, nor is `apps/harness-mcp/src/tools/tool-registry.ts`, `ontology-and-gq.tools.ts`, `libs/harness/graph/src/gq-queries.ts`. So wiring is not blocked by isImmutableTcbPath, but it requires a one-time HAND edit of gate-plugin-registry.ts (DEFAULT_GATE_PLUGINS is a static `ReadonlyArray` literal, L46-58, only element `self-dogfooding-core`; RFC cites L44-56) and of tool-registry.ts (`buildLiveMcpToolDescriptors` L60-65; RFC cites L56-63) to import the manifest. RFC never states these edits or who authors them; "learn" cannot append without editing these tracked, non-TCB files, which contradicts the "only write under tools/synthesized-plugins/" invariant (§3.3.2, REQ-1.1).
- Path-traversal hole in the snippet: Stage1 check = `!isImmutableTcbPath(p) && p.startsWith("tools/synthesized-plugins/")`. `tools/synthesized-plugins/../../libs/harness/gates/src/plugins/gate-plugin-registry.ts` passes startsWith and is not in the TCB list (isImmutableTcbPath normalizes with posix.normalize but startsWith is on the raw string). Needs `path.posix.normalize` before the prefix test. Also backslash paths fail startsWith.
- Safety gap: TCB list is only a path denylist; it does not include gate-plugin-registry.ts, self-dogfooding-plugin.ts, tools/oxlint/syntax-bans.js, .oxlintrc.json, nx.json. Promoted gate plugins are arbitrary LLM-derived TS executed in-process inside `verify` (GatePluginRegistry.evaluateFiles L66-100) with no sandbox (the RFC-0011 sandbox only covers query scripts). In effect-lfg `learn` runs unattended before verify, so no human PR review happens before the code enters gates.

## 3. `tools/` directory and Nx boundaries — FALSE (design not implementable as written)

It is NOT an Nx project/package: pnpm-workspace.yaml packages = apps/_, libs/harness/_, libs/sample/_, libs/es/_; nx.json has no tools project; no package.json/project.json under tools/. Also AGENTS.md: type:core = "no I/O"; loading a manifest of emitted files is a compile-time import so OK, but the boundary issue stands. apps/harness-mcp (type:app) could import it only if tools/ became a tagged project.

- `SkillPromoter.decide` input: `instancesCount: number`, `qualityScoreMillis: number`, `minQualityMillis: number` and an inline object type literal `{ readonly ... }` as parameter violate AGENTS.md (L77-78 branded boundary, `unbranded-primitive-boundary`, no inline object types).
