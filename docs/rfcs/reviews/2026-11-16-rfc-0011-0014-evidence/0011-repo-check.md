## Internal inconsistencies in RFC-0011

1. Ledger fields: G5 (L3.1) `(astHash, sdkNamespacesUsed, durationMicros, byteSize)` "anonymized" vs 5.3 item 4 `{scriptHash, normalizedScript, namespacesUsed, durationMicros, outcome}`. Different names (astHash vs scriptHash; sdkNamespacesUsed vs namespacesUsed), byteSize vs outcome, and normalizedScript stores source text, which is not anonymized (ADR text also says "sanitized"). RFC-0014 needs the normalized AST + literal params, so G5's hash-only form cannot feed it. Fix: single `CodemodLedgerRecord` schema incl. `kind`, `scriptHash`, `normalizedScript` (literals abstracted), `namespacesUsed`, `durationMicros`, `byteLength`, `outcome`, `taskId`; drop "anonymized" or define redaction.
2. Errors: 5.3 `evaluateReadOnlyQuery` E-channel lists 4 tagged errors; invariants/theorem and Phase 3 also imply a runtime-throw error (script exceptions) and an "output too large" path; section 10.3 CM-1 says "4 Schema.TaggedError classes" but there is no error for a script that throws, nor for ledger-write failure, nor for invalid `branch`. REQ-1.x lists only these four. Add `QueryScriptRuntimeError` (or fold into EvalQueryResult as a tagged struct) and decide behavior for ledger failure (non-fatal).
3. Latency: "< 15 ms" end-to-end (G1, 2.2, 8.1) vs Phase budgets 2 (sdk_search) + 3 (guard) + 8 (TS check) + 3 (dispatch) + serialization already >= 16 ms at p95; "11 ms" walkthrough; section 2.2 "15-20 turns" vs section 1 "10-25 turns" vs ADR "~15 turns".
4. Timeouts/limits: G4 maxScriptBytes 16,384 vs section 1 "24 KiB" is output (OK) but phase 1 lists AST depth > 40 while `EvalQueryViolationRule` has one combined `script-size-or-depth-exceeded`; `Schema.isBetweenLength(1, 16_384)` on `EvalQueryScript` means oversize scripts fail at schema decode (not as `QueryAstPolicyViolationError`), so that rule can only fire for depth.
5. Heap: worker `resourceLimits.maxOldGenerationSizeMb: 64` vs `EvalMaxHeapMb` range 16-128 and `maxHeapMb` input not exposed in `harness_eval_query` input schema (6.1 table only has timeoutMs, maxBytes). Heap limit is fixed, yet error carries `maxHeapMb`.
6. `codeGeneration: { strings: false, wasm: false }` inside a Worker while Phase 1 bans `Reflect`, `Proxy`, `Buffer`, `globalThis` - fine, but vm contexts do not share the worker's frozen intrinsics: `Object.create(null)` context still gets its own intrinsics; prototype pollution is then confined to the context, so "disjoint V8 Isolate" claim (4.2 item 2) applies to the worker, not vm. Sync bridge: `Atomics.wait` on a Worker for SDK RPC is listed as open question 2 but the main design (5.3.2) already depends on it.
7. Invariant 3 vs 4.1: AST projection roots `["libs","apps"]` (and secrets excluded) - consistent; but Theorem item 3 says `.harness/` forbidden "outside snapshot read projections" while `verify-stamp.json` is the only one listed in 3.3.
8. Stray text: section 10.3 after CM-3 contains a pasted RFC-0006 bullet list ("Eliminates existing CLI/MCP/extractor/Ollama bottlenecks ... PERF-01..05 ...") and "3. Milestone 4 ... RFC-0004", "4. Milestone 5 ... RFC-0005" which belong to a different RFC; numbering "3." repeats (CM-3, then 3.). Delete these lines.
